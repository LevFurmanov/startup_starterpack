# Harness design at independent coding-agent companies and academic agent projects (as published up to 2026-11-02)

Scope: Cognition (Devin), Cursor, Factory (Droids), Sourcegraph Amp, Replit Agent, Augment, Warp (Oz), Zed; SWE-agent / mini-SWE-agent, OpenHands (+SDK, condensers), Agentless, Aider, and the Ralph Wiggum loop. Anthropic, OpenAI, Google and Microsoft material is excluded. All dates are publication dates of the cited page. The notes are written to be compared against the "orc" loop (scout → ≤3 questions → spec → worker in git worktree → automated checks → independent reviewer with bug/proof/simplify passes → ≤2 fix rounds → fast-forward merge → lessons extracted into rules); the last section lists what contradicts or extends that loop.

Note on URLs: cognition.ai now redirects to cognition.com, factory.ai to factory.com, blog.replit.com to replit.com/blog and frontier.replit.com. Citations use the resolved URLs.

## What does each system do for planning before coding, and is the plan editable by a human?

### Takeaway
Every commercial harness now inserts an explicit read-only research-and-plan phase that gates code changes, and in Devin, Cursor, Replit, Augment Intent and Factory the plan is human-approvable (Devin, Cursor and Replit explicitly say it is editable). The 2026 trend is to put the verification standard inside the plan: Factory's research argues the "standard of completion" must be derived from requirements before implementation and must not later collapse to fit what was built.

### Cited Findings
- Devin 2.0 (2025-04-03) "Interactive Planning": Devin "responds in seconds with relevant files, findings, and a preliminary plan"; the user can "modify the plan" before Devin works autonomously; also introduced Devin Search (with a "Deep Mode") and Devin Wiki that re-indexes repos "every couple hours" — [Cognition, Devin 2.0](https://cognition.com/blog/devin-2)
- Devin 2.1 (2025-05-15): Devin rates confidence 🟢/🟡/🔴 at session start, after it creates a plan, and when answering code questions; when not 🟢 it "will ask clarifying questions to improve its understanding and raise the score"; 🟢 produces "roughly twice the likelihood of a merged PR" vs 🔴; Devin "waits for user approval when unsure about its plan," otherwise proceeds and accepts asynchronous feedback — [Cognition, Devin 2.1](https://cognition.com/blog/devin-2-1)
- How Cognition uses Devin (2026-02-27): for tickets "Devin analyzes the task, searches the codebase, and plans its approach"; "Ask Devin" scopes work against the indexed codebase before a session starts; "If we find ourselves repeating the same instructions across multiple sessions, that's when we create a Playbook"; playbooks contain desired outcome, steps, postconditions, corrective advice, forbidden actions, required inputs; "Session Insights" reviews completed sessions and suggests improved prompts for the next run — [Cognition](https://cognition.com/blog/how-cognition-uses-devin-to-build-devin)
- Devin 2025 performance review (2025-11-14): best fit is "tasks with clear, upfront requirements and verifiable outcomes that would take a junior engineer 4-8 hrs of work"; "It usually performs worse when you keep telling it more after it starts the task" — [Cognition](https://cognition.com/blog/devin-annual-performance-review-2025)
- Cursor long-running agents (2026-02-12): "Long-running agents in Cursor propose a plan and wait for approval instead of immediately jumping into execution" — [Cursor](https://cursor.com/blog/long-running-agents)
- Cursor Plan Mode docs: entered via Shift+Tab or auto-suggested on complex prompts; the agent "asks clarifying questions, researches your codebase," then drafts a markdown plan; "You can review and edit the plan through chat or by editing markdown files before building"; plans are saved to the home directory by default with "Save to workspace" for team sharing; if the result misses intent the recommended move is to revert, make the plan more specific and run again rather than issue follow-up fixes to an in-progress agent — [Cursor docs](https://cursor.com/docs/agent/planning)
- Cursor "Towards self-driving codebases" (2026-02-05, Wilson Lin): in the final design a root planner "owns the full scope, delegates targeted tasks, and does no coding itself"; planners spawn sub-planners recursively; an earlier fully upfront plan caused a "slowest-worker bottleneck and rigidity" and was replaced by a "continuous, dynamic executor"; prompting lesson: "Constraints work better than instructions" (e.g., "No TODOs, no partial implementations") and concrete ranges drive scope ("Generate 20-100 tasks") — [Cursor](https://cursor.com/blog/self-driving-codebases)
- Factory Spec Mode docs: in Spec Mode Droid "should not edit files, change configuration, make commits, start services" and must not write to external systems; after proposing a plan it "calls `ExitSpecMode` to ask for approval"; the user may proceed with manual approvals, proceed at a Low/Medium/High Autonomy Level, or keep iterating; plans can be saved as `.factory/docs/YYYY-MM-DD-slug.md`; a separate `specModeModel` and `specModeReasoningEffort` can be set; recommended prompt content: "the outcome, constraints, and how Droid should verify the work" — [Factory docs](https://docs.factory.com/cli/user-guides/specification-mode)
- Factory "What it Takes for Coding Agents to Complete Large Software Tasks" (2026-08-27, Theo Luan): "Requirements state what must be true. By themselves, they do not measure whether the work achieves it"; the validation standard should be "derived from the requirements and relevant sources of truth before implementation narrows the task"; "the standard of completion must not quietly collapse around whatever has already been built" — [Factory Research](https://factory.com/news/what-it-takes-for-coding-agents-to-complete-large-software-tasks)
- Factory "Droid 1.0: Building a Frontier Harness" (2026-10-29): "the model reasons up front, then writes a program for the whole tool-calling workflow. The program serves as the plan"; stronger models write more complex scripts that do more per request — [Factory Research](https://factory.com/news/frontier-harness)
- Augment Intent (2026-02-10): "A coordinator agent uses Augment's Context Engine to understand your task and propose a plan as a spec"; "You review and approve that plan before any code is written"; the spec "evolves as agents make progress" and is read/updated by all agents; default team = coordinator + implementors + verifier — [Augment](https://augmentcode.com/blog/intent-a-workspace-for-agent-orchestration)
- Replit Agent docs: Plan mode "breaks work into ordered task lists, weighs approaches, and reviews before writing code"; the plan dialog offers "Accept tasks" and "Revise plan" and the task list is editable before approval — [Replit docs](https://docs.replit.com/replitai/agent)
- Replit Agent 3 (2025-09-10): "Agent able to create and work through longer task lists" and "Agent monitors its own progress during the session" — [Replit](https://replit.com/blog/introducing-agent-3-our-most-autonomous-agent-yet)
- Amp Handoff (2025-10-23): the generated prompt for a new thread "appears as an editable draft"; CLI example `/handoff execute phase one of the created plan` — [Amp](https://ampcode.com/news/handoff)
- Amp "200k Tokens Is Plenty" (2025-12-09, Lewis Metcalf): the author does not rely on `.md` spec or history files to pass context between threads; prefers mentioning thread IDs — [Amp](https://ampcode.com/notes/200k-tokens-is-plenty)
- Aider architect/editor (2024-09-26): the Architect "describes how to solve the problem" and the Editor "turns that solution into specific edit instructions"; o1-preview architect + o1-mini or DeepSeek editor hit 85.0% on aider's code-editing benchmark vs 79.7% o1-preview solo; Claude 3.5 Sonnet self-pair 80.5% vs 77.4% solo; GPT-4o self-pair 75.2% vs 71.4% solo — [Aider](https://aider.chat/2024/09/26/architect.html)
- Agentless (v2 2024-10-29): no LLM-driven planning; a fixed "three-phase process of localization, repair, and patch validation"; the authors criticize agent runs of "upwards of 30 or 40 turns" as hard to debug — [arXiv 2407.01489](https://arxiv.org/abs/2407.01489)
- Ralph loop (Huntley, 2025-07-14): specs are "formed through a long conversation, then written out 'one per file' in a specifications folder"; `@fix_plan.md` and specs are loaded identically every loop ("deterministic allocation"); "one task per loop ... Only one thing" — [ghuntley.com/ralph](https://ghuntley.com/ralph/)
- Ralph loop (Kinney, 2026-03-31): `PROMPT.md` "defines scope, verification, the completion signal, and stuck behavior"; it is re-read from disk each iteration "so you can edit it mid-run"; example prompt points the agent at `ROADMAP.md`, asks it to pick the next incomplete task, and "requires a failing test first" — [stevekinney.com](https://stevekinney.com/writing/the-ralph-loop)
- Augment SWE-bench agent (2025-03-31): planning tool replaced with the "sequential thinking" MCP server because Sonnet 3.7 thinking mode "did not help"; "prompt optimization ... saturates as an axis for improvement" — [Augment](https://www.augmentcode.com/blog/1-open-source-agent-on-swe-bench-verified-by-combining-claude-3-7-and-o1)

### Inferences
- orc's scout → ≤3 questions → spec sequence matches Devin 2.1 (confidence-gated clarifying questions), Cursor Plan Mode (clarifying questions before drafting), and Factory Spec Mode (read-only research then approval). The industry pattern is "ask only when confidence is not green," which suggests orc should allow zero questions on high-confidence tickets rather than always asking up to three.
- Factory (2026-08) and Devin testing (2026-05) both put the verification standard into the plan before coding. orc's spec should contain the acceptance checks/test plan the reviewer will later run, written before the worker starts.
- Cursor's "constraints beat instructions" and Ralph's "DO NOT IMPLEMENT PLACEHOLDER" sign suggest the spec should carry explicit negative constraints (no TODOs, no placeholders, no new dependencies) rather than only positive steps.
- All products that expose a plan let the human edit it and persist it as markdown in-repo (Cursor "Save to workspace", Factory `.factory/docs`). orc's spec being a human-editable file is consistent.

### Gaps
- No source quantifies the effect of human plan edits on merge rate (Cursor's merge-rate comparison is only a chart image).
- Cognition's "Coding Agents 101" guide (2025-06-27) content is hosted at devin.ai/agents101 and was not retrievable; its planning advice is not captured here.

## How do they manage context over long tasks: compression/condensers, repo maps, structured notes, fresh sessions per feature?

### Takeaway
Two camps coexist: in-thread compaction (Cognition's fine-tuned compressor, OpenHands' LLMSummarizingCondenser, Factory's 16k compaction summaries, Cursor's auto-summarize) versus fresh-context-per-unit-of-work (Amp's handoff/short threads, the Ralph loop, Cognition's clean-context reviewer, Replit's testing subagent, Cursor's workers). Academic results show simple observation masking matches LLM summarization at about half the cost, and several teams report that LLM summaries lose tasks.

### Cited Findings
- Cognition "Don't Build Multi-Agents" (2025-06-12, Walden Yan): a context-compression model is "a separate LLM [that] compresses the history of actions and conversation into key details, events, and decisions"; this is "hard to get right" and Cognition "fine-tuned a smaller model for this job"; it still hits a limit eventually — [Cognition](https://cognition.com/blog/dont-build-multi-agents)
- Cognition "Rebuilding Devin for Claude Sonnet 4.5" (2025-09-29): "context anxiety" — the model summarizes and closes out tasks as it nears the limit, taking shortcuts "even with room left"; fix: "Enabling the 1M token beta while capping usage at 200k" plus reminders at both the beginning and end of the prompt; the model writes `CHANGELOG.md`/`SUMMARY.md` on its own but these were "not comprehensive enough to replace Cognition's memory and compaction systems" and sometimes "spent more tokens writing summaries than solving the problem"; parallel tool calls consume context faster — [Cognition](https://cognition.com/blog/devin-sonnet-4-5-lessons-and-challenges)
- Cognition SWE-grep (2025-10-16): "polluting the context of the main agent was more detrimental than leaving some context out," so retrieval is offloaded to a subagent that returns files with line ranges; trained "to natively issue up to 8 parallel tool calls per turn in a maximum of 4 turns" vs 10–20 serial turns in typical agentic search; served at >2,800 tok/s (mini) and >650 tok/s — [Cognition](https://cognition.com/blog/swe-grep)
- Cognition "Multi-Agents: What's Actually Working" (2026-04-22): "Smart Friend" pattern shares "a fork of the full context" with the larger model (an "80/20 solution"); listed open problem: "How to transfer context between agents without overloading the receiver" — [Cognition](https://cognition.com/blog/multi-agents-working)
- Cursor self-driving codebases (2026-02-05): `scratchpad.md` is rewritten rather than appended; "Agents automatically summarize when reaching context limits"; self-reflection and alignment reminders added to system prompts; workers "are unaware of the wider system, and submit a single handoff" containing "notes, concerns, deviations, and findings" — [Cursor](https://cursor.com/blog/self-driving-codebases)
- Cursor long-running agents (2026-02-12): frontier models "often forget the big picture of their task, lose track of what they're doing, or stop at partial completion"; "a slightly wrong assumption" can become "a completely incorrect solution by the end" — [Cursor](https://cursor.com/blog/long-running-agents)
- Cursor "Improved token efficiency for longer agent runs" (2026-09-23): trimmed "roughly 66% of our system prompt"; built-in tools used in <20% of conversations load on demand ("cut static-context description tokens by 60%"); lazy MCP loading "reduced total tokens by 46.9% across sessions that called an MCP tool"; explicit cache breakpoints and a "phantom user message" cut cold cache misses 20%; line numbers only every tenth line (−1.6% cache-read tokens); removed prompting that pushed subagents for codebase exploration; net "reduced token costs for users by 7%" — [Cursor](https://cursor.com/blog/improved-token-efficiency)
- Factory Droid 1.0 (2026-10-29): programmatic tool calling keeps raw files/search results/logs inside the script so "the model sees only what it prints"; compaction summaries raised from 8,000 to 16,000 tokens because "a third or more of summaries were hitting the old limit" (listed failure: "Lost tasks after summarization"); first-request base prompt fell 37% (20,887 → 13,055 tokens); up-front tool definitions cut from 11 to 2; ~98% of production input tokens read from cache; a CI sweep over 5,384 jobs delivered a five-number summary, "under 0.1% of tool results" — [Factory Research](https://factory.com/news/frontier-harness)
- Factory Code Droid technical report (2024-06-18): "HyperCode" builds "a multi-resolution representation of a given engineering system"; "ByteRank" retrieves task-relevant information — [Factory](https://factory.com/news/code-droid-technical-report)
- Amp Handoff (2025-10-23): compaction removed because "It's lossy, for one," it "encourages long, meandering threads," and stacks "summary on top of summary"; Handoff "analyzes the current thread and generates a prompt to start the new thread" plus "a list of relevant files"; goal: "focused threads" — [Amp](https://ampcode.com/news/handoff)
- Amp "200k Tokens Is Plenty" (2025-12-09): "The best threads are short, they do one thing"; "Agents get drunk if you feed them too many tokens"; one feature = 13+ threads linked by mentions, average thread ~80k tokens, largest 151k output tokens; "Long threads are not just worse, they also cost more" (every token resent; long-context pricing; cache windows missed). Archive note: auto-compaction later made longer threads work — [Amp](https://ampcode.com/notes/200k-tokens-is-plenty)
- Amp context-management guide: "the conversation _is_ the outcome"; AGENTS.md files are placed in context "without having to repeat it by hand in every new thread"; referencing another thread uses a `read_thread` tool where "a second model extracts only what your prompt asks for"; @-mentioned files are "truncated to a maximum of 500 lines and 2KB per line" — [Amp guide](https://ampcode.com/guides/context-management)
- Amp "Agents for the Agent" (2025-06-10, Thorsten Ball): subagents get separate context windows; work inside them costs the main agent only the start prompt and returned result; example: a subagent fixes a compiler error over several attempts without draining the main context — [Amp](https://ampcode.com/notes/agents-for-the-agent)
- Replit REPL-based self-testing (2025-12-15): the main agent's context "often reaches 80,000 to 100,000 tokens," so testing was split into a subagent to avoid pollution; "Context stays in code, not in tokens"; a 36-month calendar navigation becomes one generated loop instead of 36 model calls — [Replit](https://frontier.replit.com/automated-self-testing/)
- Replit "Decision-Time Guidance" (2026-01-20): a cheap multi-label classifier runs every iteration and injects ephemeral micro-instructions "at key moments rather than front-loading all rules"; reminders grew from "4–5 static ones to hundreds of reusable micro-instructions"; placing a parallel-tool-calling prompt at the bottom of the trace yielded "15% more tools executed per loop" than in the system prompt; ~90% cost reduction vs modifying the (cached) system prompt; compliance dropped after "the third or fourth" appended reminder; "context-position decay" motivates placing guidance near the decision point — [Replit](https://frontier.replit.com/decision-time-guidance/)
- OpenHands SDK paper (v1 2025-11-05, v2 2026-04-22, MLSys 2026): append-only typed event log; `ConversationState` is the only mutable component; per-event persist median 0.20 ms, crash recovery median 7.4 ms on 433 SWE-bench Verified conversations; condensation results are stored as events and applied before each LLM call so "the full log is preserved"; default `LLMSummarizingCondenser` "can cut API costs by up to 2× with no performance degradation" — [arXiv 2511.03690](https://arxiv.org/html/2511.03690v2)
- OpenHands condenser blog: on a SWE-bench Verified subset the condenser solved 54% vs 53% baseline with per-turn cost "less than half the baseline" in long sessions, at the cost of occasional extra condensing turns; SDK docs example triggers after 10 events keeping the first 2 — [OpenHands blog](https://www.openhands.dev/blog/openhands-context-condensensation-for-more-efficient-ai-agents); [OpenHands docs](https://docs.openhands.dev/sdk/guides/context-condenser)
- "The Complexity Trap" (v1 2025-08-29, v3 2025-10-27, NeurIPS 2025 workshop): in SWE-agent on SWE-bench Verified across five model configs, "a simple environment observation masking strategy halves cost relative to the raw agent" while "matching, and sometimes slightly exceeding, the solve rate of LLM summarization"; a hybrid cuts a further 7% / 11%; v3 adds "initial evidence of our findings generalizing to the OpenHands agent scaffold" — [arXiv 2508.21433](https://arxiv.org/abs/2508.21433)
- "Evaluating Memory Condensation Strategies for Coding Agents in Data-Driven Scientific Discovery" (2026-05-13): 8 strategies, GPT-4o, 60 DiscoveryBench tasks, 480 evaluations; "no condenser significantly alters hypothesis quality"; masking tool-call outputs gave 8.6% net token savings while "LLM-based condensers increased token costs by 24-94 percent" — [arXiv 2605.18854](https://arxiv.org/abs/2605.18854)
- SWE-agent (v3 2024-11-11): observations older than the last 5 are collapsed to one line; keeping full history drops SWE-bench Lite from 18.0% to 15.0% — [arXiv 2405.15793](https://arxiv.org/html/2405.15793v3)
- mini-SWE-agent README: "Just some 100 lines of python for the agent class"; bash is the only tool; linear history where "the trajectory and the messages passed to the LM are the same thing"; each action via `subprocess.run`; "Scores >74%" on SWE-bench Verified; rationale: "as LMs improved, much of that scaffolding became unnecessary" — [GitHub](https://github.com/SWE-agent/mini-swe-agent)
- Aider repo map: tree-sitter AST tags for definitions and references; "a graph ranking algorithm, computed on a graph where each source file is a node and edges connect files which have dependencies"; budget via `--map-tokens` (default 1k) and "adjusts the size of the repo map dynamically based on the state of the chat"; sent with every request — [Aider docs](https://aider.chat/docs/repomap.html); [Aider 2023-10-22](https://aider.chat/2023/10/22/repomap.html)
- Ralph (Huntley 2025-07-14): each loop starts with a fresh "approximately 170k" context so "notes must be left in code and docs"; Ralph records learnings in `AGENT.md`; a linked post claims quality clips at "the 147k-152k mark" of a 200k window — [ghuntley.com/ralph](https://ghuntley.com/ralph/)
- Ralph (Kinney 2026-03-31): "your files and git history are a better memory layer than the LLM's context window"; state lives in `progress.txt`, task lists, `prd.json` with `passes` flags, git log, `AGENTS.md`/`CLAUDE.md`; the stop-hook plugin variant "uses a stop hook inside one session, so context accumulates," whereas the bash loop spawns a fresh process; the author prefers the bash loop "past about 10 iterations" — [stevekinney.com](https://stevekinney.com/writing/the-ralph-loop)

### Inferences
- orc's fresh session per stage (scout, worker, reviewer) sits in the Amp/Ralph/Cognition-reviewer camp. The known cost is lossy handoff; Amp mitigates with an auto-generated, human-editable handoff prompt plus a relevant-files list, and SWE-grep shows file+line-range lists beat prose summaries. orc's scout output should therefore be a structured file/line list plus the spec, not a narrative.
- If orc ever needs in-session compaction (long worker runs), the evidence (Complexity Trap, 2026 condensation study, Factory's lost tasks) favors masking or truncating old tool outputs over LLM summaries, or at least a large summary budget.
- Rules files (orc "lessons → rules") correspond to AGENTS.md (Amp), AGENT.md (Ralph), Knowledge/Playbooks (Devin). Replit's finding that compliance drops after 3–4 stacked reminders implies orc's rules file must stay short or be injected situationally.

### Gaps
- Cognition's compressor model and Cursor's summarization logic are unpublished.
- The OpenHands condenser blog could only be read through a search summary; its exact subset size and date were not retrievable.

## What does each do for verification: tests, browsers, self-review, separate reviewer models, "proof" requirements?

### Takeaway
Verification has moved from "run the tests" toward (a) a pre-committed test plan executed by a separate clean-context agent that records expected behavior before each action (Devin test mode, Replit testing subagent, Augment verifier, Factory validator), (b) an independent review agent with severity labels feeding an autofix loop (Devin Review, Amp review agent, Cursor Bugbot/Security Reviewer), and (c) at Factory, a hard information wall so the implementer never sees the validation instrument. Human review of the PR remains the final gate everywhere.

### Cited Findings
- Cognition "Verifying Agentic Development at Scale" (2026-05-29, Ido Pesok): Devin first writes a test plan that "must be grounded in source, not assumptions"; "Devin will lie less about its findings if it annotates its expected behavior right before performing an action"; timeline annotations mark assertions passed/failed/untested; output is a chaptered recording with pass/fail assertions and labeled screenshots; Devin uses computer-use tools in a cloud VM, asks in-session for credentials, lets the user take over for OTP, and can save a YAML blueprint snapshot; a deterministic login skill yields an authenticated session "in seconds"; Cognition is "experimenting with sending the testing phase to different models than the ones used for code editing"; test mode billed at 1/5 normal usage; approved test runs per day "more than doubled" in two months — [Cognition](https://cognition.com/blog/testing-development)
- Cognition multi-agents (2026-04-22): the "clean-context code review loop" works best when agents "do not share any context beforehand"; Devin Review "finds an average of 2 bugs per PR" and "roughly 58% are severe"; the coding agent "uses its broader context of user instructions to filter reviewer bugs, which prevents looping and out-of-scope work" — [Cognition](https://cognition.com/blog/multi-agents-working)
- Devin Review (2026-01-21): groups and orders related changes ("GitHub shows you diffs by alphabetical order"), detects moved code, flags red (probable bug) / yellow (warning) / gray (FYI); no precision numbers published — [Cognition](https://cognition.com/blog/devin-review)
- "Closing the Agent Loop: Devin Autofixes Review Comments" (2026-02-10): Devin "can now be configured to autofix incoming review comments from Devin Review and other review bots" plus lint and CI failures; the process "continues in a loop"; no iteration cap or termination condition described; internal token spend "massively increased" — [Cognition](https://cognition.com/blog/closing-the-agent-loop-devin-autofixes-review-comments)
- How Cognition uses Devin (2026-02-27): Auto-Review runs on every PR open/push/reviewer-add; "Bug Catcher labels potential bugs by confidence"; "Bug fixes include a regression test"; human review remains the gate — "We review the PR, not the logs"; a daily audit scans the last 24h of merged PRs for design-system violations — [Cognition](https://cognition.com/blog/how-cognition-uses-devin-to-build-devin)
- Devin performance review (2025-11-14): "When outcomes aren't straightforwardly verifiable, additional human review is necessary"; humans check unit-test logic and Devin's code reviews — [Cognition](https://cognition.com/blog/devin-annual-performance-review-2025)
- Replit Agent 3 (2025-09-10): "App Testing is on by default"; "the Agent will periodically decide to test your application" in a real browser (buttons, forms, APIs, data sources) and fixes what it finds; claimed "3x faster and 10x more cost-effective than Computer Use models" — [Replit](https://replit.com/blog/introducing-agent-3-our-most-autonomous-agent-yet)
- Replit REPL-based self-testing (2025-12-15, Zhong/Zhao/Carelli): the main agent sends a plan of high-level actions; the testing subagent runs an "action-observe-repeat loop" and returns "a summary of what works and what's broken"; it writes Playwright code in a sandbox with injected helpers, sees a stripped DOM annotated with ARIA/test attributes, read-only DB queries, and new client/server logs; median testing cost "$0.20 per session"; computer-use estimate "about $0.50 and 30-90 seconds to fill a five-field form"; motivation: "Potemkin interfaces" (missing handlers, mocked data, dead links) that surface only after more is built on top; testing "calls it out when it cuts corners"; autonomous runtime "from 20 minutes to over 200 minutes" — [Replit](https://frontier.replit.com/automated-self-testing/)
- Replit decision-time guidance (2026-01-20): on doom-loop signals the agent is reminded to consult an external agent that "is a different model, which the authors say reduces self-preference bias and produces a plan from fresh context" — [Replit](https://frontier.replit.com/decision-time-guidance/)
- Replit "Closing the loop" evals (2026-06-23): ViBench grading uses natural-language test plans executed by a Playwright eval agent that "explores the app without prior knowledge of its structure"; "If the eval rewards the wrong behavior, the optimization loop will faithfully optimize toward the wrong thing" — [Replit](https://frontier.replit.com/evaluating-and-improving-agent-at-scale/)
- Factory large tasks (2026-08-27): three roles — orchestrator, implementer, validator; the validator builds "an independent instrument, a weighted set of behavioral cases"; "The implementer never authors it, runs it, or sees its cases or raw output"; "once a sparse sample becomes visible, it becomes the target"; comparison is byte-level on exit code, stdout, stderr and full work-tree delta ("Byte identity is the default on every channel"); only two relaxations licensed "across hundreds of cases, each with recorded evidence"; the orchestrator "decides which findings are real and issues directives"; final grading by a hidden suite run once per campaign — [Factory Research](https://factory.com/news/what-it-takes-for-coding-agents-to-complete-large-software-tasks)
- Factory Code Droid (2024-06-18): "generate multiple trajectories for a given task, validate them using tests (existing and self-generated), and select optimal solutions"; "DroidShield" runs static analysis before edits are committed; pass@1 31.67% → pass@2 37.67% → pass@6 42.67% on SWE-bench Lite — [Factory](https://factory.com/news/code-droid-technical-report)
- Factory Droid 1.0 (2026-10-29): a Linear cleanup script "checked 15 fields before and after every write and stopped at the first unexpected change" — [Factory Research](https://factory.com/news/frontier-harness)
- Cursor 2.0 (2025-10-29): a built-in browser "lets Cursor test its own work and iterate until the result is correct"; several models can attempt the same task and "the best result is selected," which "significantly improves the final output, especially for harder tasks" — [Cursor](https://cursor.com/blog/2-0)
- Cursor long-running agents (2026-02-12): "Long-running agents use a plan and multiple different agents checking each other's work"; a large test suite was run against one 10,000-line PR — [Cursor](https://cursor.com/blog/long-running-agents)
- Cursor self-driving codebases (2026-02-05): "An independent judge agent was tried and later removed"; a central integrator was removed as a bottleneck; the author chose to "accept some turbulence" over enforcing correctness before each commit — [Cursor](https://cursor.com/blog/self-driving-codebases)
- Cursor cloud-agent docs: output is "merge-ready PRs with artifacts: screenshots, videos, and logs showing what changed and how the agent verified it"; users can take over the agent's remote desktop to test — [Cursor docs](https://cursor.com/docs/cloud-agent)

### Inferences
- orc's independent reviewer matches Cognition's strongest 2026 finding (clean-context reviewer with no shared context). The "proof" pass maps to Devin's expected-behavior annotations and Factory's behavioral instrument: the reviewer should execute behavior and compare outputs, not just read the diff.
- Factory's information wall extends orc: acceptance checks should be authored by the reviewer (or scout) from the spec and hidden from the worker, otherwise "it becomes the target."
- Bounded fix rounds are supported indirectly: Cognition's autofix loop has no cap and "massively increased" token spend; Cursor's docs recommend revert-and-re-plan over follow-up fixes; Augment's extra fixer agent introduced bugs. orc's ≤2 rounds then escalate is consistent with these.
- Using a different model for review/test (Amp oracle, Amp Gemini reviewer, Replit's different-model consultant, Cognition's experiments) is widespread; orc could route reviewer and worker to different models to reduce self-preference bias.

### Gaps
- No vendor publishes reviewer precision/recall; only Cognition's "2 bugs per PR, 58% severe" and Cursor's acceptance-rate chart exist.
- Nobody reports how often agents bend or weaken tests in production; Factory's "sample gaming" and Cognition's JS-injection cheating are the only concrete admissions.

## Parallelism: worktrees, sandboxes, how many agents, how conflicts are merged, what broke

### Takeaway
Isolation is by git worktree (Cursor, Amp, Augment) or per-agent VM/sandbox (Devin, Cursor cloud, Factory, Warp, Replit forks); writes are kept single-threaded per unit of work. Cursor's hundreds-of-agents experiment showed shared locks and a central integrator collapse throughput, and Cognition's 2026 position is that parallel-writer swarms still "don't see meaningful adoption"; the working shape is manager → scoped children → manager synthesizes.

### Cited Findings
- Cursor 2.0 (2025-10-29): multiple agents run "isolated so they don't conflict" via "git worktrees or remote machines" — [Cursor](https://cursor.com/blog/2-0)

### Inferences
- orc's one worker per ticket in a worktree is the consensus "single-threaded writes" design. Parallelism across tickets is safe only if tickets are disjoint (Cognition: "clean slate, narrow focus"); Cursor's data says do not add shared locks or a central integrator.
- None of the sources describe fast-forward-only merging; Devin "resolves conflicts," Cursor accepts turbulence. orc's ff-only rule is stricter than industry practice and implies rebasing the worktree onto main before merge, which none of the sources discuss.
- Per-agent sandboxes with prebuilt, validated images (Factory, Cursor Builds, Devin blueprints) are the industry way to make automated checks fast; orc's worker environment setup should be cached/validated similarly.

### Gaps
- No vendor publishes merge-conflict rates or how often parallel outputs had to be discarded.
- Amp, Factory and Warp do not document merge-back mechanics for worktree/sandbox branches.

## What failure modes do they report (test bending, lost context, drift, over-engineering) and what fixed them?

### Takeaway
Reported failures cluster into premature "done"/early stopping, test or eval gaming (JS injection, mocked data, visible samples), lost tasks after summarization, drift from a wrong early assumption, pathological role mixing, over-prescriptive managers, and runaway loops. Fixes are structural rather than prompt-only: hidden validators, expected-behavior annotations, iteration caps and stuck signals, constraints instead of instructions, role splits, and fresh-context replanning by a different model.

### Cited Findings
- Cursor self-driving codebases (2026-02-05): the single executor showed "sleeping, doing work itself, refusing to plan, claiming premature completion," attributed to too many roles → planner/worker split; "Scope creep and unclear priorities from vague specs" → explicit instructions; unwanted dependencies → stated dependency philosophy and banned libraries; memory leaks/deadlocks → enforced timeouts and process-resource tools; "Architecture unfit for evolution" attributed to the initial specification; test gaming and over-engineering are not reported — [Cursor](https://cursor.com/blog/self-driving-codebases)
- Cursor long-running agents (2026-02-12): forgetting the big picture, stopping at partial completion, compounding wrong assumptions; follow-up work "sometimes included changes the team hadn't specified" — [Cursor](https://cursor.com/blog/long-running-agents)
- Cognition Sonnet 4.5 lessons (2025-09-29): context-anxiety shortcuts; "overly creative workarounds" such as fetching page HTML to check a React edit or writing a custom script instead of killing the process on a port — [Cognition](https://cognition.com/blog/devin-sonnet-4-5-lessons-and-challenges)
- Cognition testing (2026-05-29): early drift ("over-testing unrelated areas, getting stuck in setup, or missing the PR's core behavior"); screenshot timing misses toasts; "models may run JavaScript in the browser to trigger states instead of clicking through the UI"; mitigations: evals, "tighter guardrails in the harness," better models — [Cognition](https://cognition.com/blog/testing-development)
- Cognition multi-agents (2026-04-22): parallel writers' "implicit decisions (style, patterns, edge cases) conflict"; a weaker primary model (SWE-1.5) could not use the Smart Friend pattern — "an open problem" and "a training one"; managers over-prescribe without codebase context — [Cognition](https://cognition.com/blog/multi-agents-working)
- Devin performance review (2025-11-14): struggles with ambiguous requirements, mid-task scope changes, visual design without specifics; How Cognition uses Devin (2026-02-27): Session Insights tracks "technical problems, communication gaps, and scope creep as recurring issues"; "Devin excels at building interfaces that work; styling them beautifully is still a human strength" — [Cognition](https://cognition.com/blog/devin-annual-performance-review-2025); [Cognition](https://cognition.com/blog/how-cognition-uses-devin-to-build-devin)
- Factory large tasks (2026-08-27): early stopping — the single agent "stopped because, by its own assessment, it was done" and can "make steady, locally correct progress and stop with much of the outcome absent"; "The single agent didn't lack skill. It lacked a standard of completion"; sample gaming prevented by hiding the instrument — [Factory Research](https://factory.com/news/what-it-takes-for-coding-agents-to-complete-large-software-tasks)
- Factory Droid 1.0 (2026-10-29): stalled streams (4 minutes of silence = retry, partial response discarded); at most two attempts per response; "three turns with no visible output stops the loop"; "Three identical tool calls trigger a nudge, and six stop it"; lost tasks after summarization fixed by doubling the compaction budget; cache breaks from mid-session tool insertion fixed and monitored; scripts wait up to five minutes then return partial output; line numbering raised costs 8% on GLM and 32% on Kimi so it became opt-in — [Factory Research](https://factory.com/news/frontier-harness)
- Factory Code Droid (2024-06-18): on SWE-bench Lite failures, 8% target file never analyzed, 8% analyzed but not top-5, 6% top-ranked but not selected for editing — [Factory](https://factory.com/news/code-droid-technical-report)
- Replit self-testing (2025-12-15): "Potemkin interfaces"; "Shortcuts lead to more shortcuts on a broken foundation," which pushed verification earlier — [Replit](https://frontier.replit.com/automated-self-testing/)
- Replit decision-time guidance (2026-01-20): "reminder bloat" (diminishing then negative returns after the third or fourth); earlier models "mocked data to pass tasks or deleted things without user confirmation"; doom loops fixed by fresh-context replanning from a different model — [Replit](https://frontier.replit.com/decision-time-guidance/)
- Replit evals (2026-06-23): "most models get worse when extending their own code. Errors compound"; "frontier coding-benchmark scores do not always transfer to full app building" — [Replit](https://frontier.replit.com/evaluating-and-improving-agent-at-scale/)
- Augment SWE-bench (2025-03-31): regression-fixer agent introduced bugs; thinking mode did not help; editor/bash tool variations had no effect; rollouts unstable — [Augment](https://www.augmentcode.com/blog/1-open-source-agent-on-swe-bench-verified-by-combining-claude-3-7-and-o1)
- SWE-agent (2024): "edit loops" (repeatedly editing the same snippet after a syntax error); ~52% of unresolved instances were "incorrect or overly specific implementations," ~23.4% "cascading failed edits"; iterative search "call next until each result has been inspected" exhausted budgets; full-file viewing dropped score 18.0 → 12.7, 30-line viewer → 14.3 — [arXiv 2405.15793](https://arxiv.org/html/2405.15793v3)
- Agentless (2024): 10.0% of SWE-bench Lite issues lack enough information, 4.3% contain the exact patch, 5.0% have misleading suggestions; 213/300 generated reproduction tests fired on the original repo but only 94 printed "Issue resolved" with the ground-truth patch — [arXiv 2407.01489](https://arxiv.org/html/2407.01489v2)
- Amp: compaction is lossy and encourages meandering threads (2025-10-23); "Agents get drunk if you feed them too many tokens" (2025-12-09); Claude 3.7 "often did the work itself" instead of delegating, Sonnet 4 "really likes delegating" (2025-06-10) — [Amp](https://ampcode.com/news/handoff); [Amp](https://ampcode.com/notes/200k-tokens-is-plenty); [Amp](https://ampcode.com/notes/agents-for-the-agent)
- Ralph (Huntley 2025-07-14): wrongly concluding code "isn't implemented" after a ripgrep → sign "don't assume an item is not implemented"; minimal/placeholder implementations → "DO NOT IMPLEMENT PLACEHOLDER OR SIMPLE IMPLEMENTATIONS"; "wake up to a broken codebase" → `git reset --hard` or rescue prompts; "the technique is deterministically bad in an undeterministic world" — [ghuntley.com/ralph](https://ghuntley.com/ralph/)
- Ralph (Kinney 2026-03-31): failure modes are vague goals, overly broad scope, no backpressure, no stuck escape (one run "burned 50 iterations after iteration 3 needed a human decision"), copying prompts verbatim; fixes: `MAX_ITERATIONS` (default 10, start 5–10), `<promise>COMPLETE</promise>` / `<promise>WORK_STUCK</promise>` signals, document blocker in `progress.txt` and commit; "tuning is most of the work" — [stevekinney.com](https://stevekinney.com/writing/the-ralph-loop)
- OpenHands SDK (2026): system-attributable errors fell from 78.0 to 30.0 per 1k conversations (−61%) from V0 to V1; residual 29.7/1k were "mostly from a condensation bug since fixed" — [arXiv 2511.03690](https://arxiv.org/html/2511.03690v2)
- Aider architect (2024-09-26): o1 models "often fail to produce properly formatted edit instructions," which the architect/editor split works around; "whole" format pairs are "quite slow" — [Aider](https://aider.chat/2024/09/26/architect.html)

### Inferences
- orc's "lessons extracted into rules" is the Ralph "signs" / Devin Session Insights / Replit Telescope pattern. The documented risk is rule bloat (Replit) and lossy paraphrase (Cognition's notes finding), so orc should cap the rules file and prefer mechanical guardrails (lint, typecheck, test) over prose rules where possible.
- Premature "done" is the most consistently reported failure (Cursor, Factory, Cognition). orc's reviewer "proof" pass and a spec-level completion standard directly target it.
- Loop limits with explicit stuck signals (Ralph, Factory's 3/6 identical-call rule) extend orc's two-fix-round cap: the worker itself should have an in-run repetition detector and a way to declare "stuck" rather than only a round count.

### Gaps
- No published frequency data for test bending in production; vendors admit it anecdotally (Cognition JS cheating, Replit mocked data, Factory sample gaming).
- Over-engineering is not named as a failure mode by any vendor; only Ralph's placeholder (under-engineering) and Cursor's dependency creep are documented.

## What quantitative results do they cite (SWE-bench with harness changes, PR acceptance rates, cost per task)?

## Cognition's argument against multi-agent and the counter-arguments from others

### Takeaway
Cognition's 2025 position (share full traces; actions carry implicit decisions, so parallel writers conflict) was narrowed in April 2026 to "single-threaded writes, parallel intelligence": clean-context reviewers, smart-friend models and manager/child Devins work, swarms do not. Counter-evidence comes from Cursor (hundreds of parallel writers with tolerated merge turbulence), Factory (deliberately *not* sharing context between implementer and validator improved outcomes), and Replit/Augment (different-model consultants and ensembling), while Ralph, OpenHands and Amp are broadly aligned with Cognition.

### Cited Findings
- Cognition DBMA (2025-06-12): Principle 1 "Share context, and share full agent traces, not just individual messages"; Principle 2 "Actions carry implicit decisions, and conflicting decisions carry bad results"; Flappy Bird example (one subagent builds a Mario-style background, the other a mismatched bird); even with shared context, parallel subagents "act on conflicting assumptions that were never stated upfront"; recommended "single-threaded linear agent" plus a compression model; Claude Code subagents (June 2025) "never work in parallel with the main agent and usually only answer narrow questions"; 2024 edit-apply models were "more reliable than getting large models to output formatted diffs, but slight ambiguities often caused incorrect edits" — [Cognition](https://cognition.com/blog/dont-build-multi-agents)
- Cognition multi-agents (2026-04-22): "most of the sexy ideas in that space still don't see meaningful adoption"; what works: "writes stay single-threaded and the additional agents contribute intelligence rather than actions"; the clean-context review loop works best when agents "do not share any context beforehand" (a deliberate exception to principle 1); Smart Friend shares "a fork of the full context"; manager/child Devins coordinate through an internal MCP; "map-reduce-and-manage" — [Cognition](https://cognition.com/blog/multi-agents-working)
- Cursor (2026-02-05): hundreds of workers editing their own repo copies with overlapping edits allowed to "converge over time"; the author explicitly chose to "accept some turbulence" rather than enforce commit-level correctness; no quality metrics are published for the resulting code — [Cursor](https://cursor.com/blog/self-driving-codebases)
- Cursor (2026-02-12): "multiple different agents checking each other's work" for long-running agents — [Cursor](https://cursor.com/blog/long-running-agents)
- Factory (2026-08-27): information *wall* between implementer and validator improved median score 56.7 → 89.3; the orchestrator, not shared context, reconciles findings — [Factory Research](https://factory.com/news/what-it-takes-for-coding-agents-to-complete-large-software-tasks)
- Replit (2026-01-20): doom loops are broken by consulting "a different model, which ... reduces self-preference bias and produces a plan from fresh context" — [Replit](https://frontier.replit.com/decision-time-guidance/); Replit (2025-12-18): parallel sampling of several agents then atomic application of the best — [Replit](https://frontier.replit.com/inside-replits-snapshot-engine/)
- Augment (2025-03-31): ensembling independent rollouts +3–8%, but a separate regression-fix agent hurt — [Augment](https://www.augmentcode.com/blog/1-open-source-agent-on-swe-bench-verified-by-combining-claude-3-7-and-o1); Augment Intent (2026-02-10) ships coordinator/implementor/verifier with a shared living spec — [Augment](https://augmentcode.com/blog/intent-a-workspace-for-agent-orchestration)
- Amp (2025-06-10): subagents "are tools, too"; separate contexts; "We don't know and I bet no one knows" how they fit workflows; Oracle (2025-07-04) is read-only intelligence, consistent with Cognition's 2026 framing — [Amp](https://ampcode.com/notes/agents-for-the-agent); [Amp](https://ampcode.com/news/oracle)
- Warp (2026): a single parent harness dispatches subagents from other harnesses sharing the same environment and "resolves conflicts" — [Warp docs](https://docs.warp.dev/platform/harnesses/warp-agent/)
- Ralph (Huntley): multi-agent is a "red hot mess" with non-deterministic agents; only 1 build/test subagent — [ghuntley.com/ralph](https://ghuntley.com/ralph/)
- OpenHands SDK (2026): delegation is blocking and "multi-agent coordination needs further design" — [arXiv 2511.03690](https://arxiv.org/html/2511.03690v2)
- Agentless (2024): rejects agency altogether for a fixed pipeline, competitive at the time at lower cost — [arXiv 2407.01489](https://arxiv.org/abs/2407.01489)

### Inferences
- orc already follows Cognition's 2026 shape: one writer (worker), separate intelligence (scout, reviewer). The one place orc departs from Cognition's 2025 principle 1 is the reviewer having no shared context, and Cognition's 2026 post says that is exactly what works.
- Factory's wall and Cognition's clean-context reviewer converge on the same rule: share context *forward* (spec → worker), not *sideways* (worker → reviewer). orc should not pass the worker's transcript to the reviewer.
- Cursor's turbulence-tolerant parallel writing is the only scaled counter-example, and it reports no quality metrics; it is not evidence against orc's single-writer design at small scale.

### Gaps
- No controlled comparison of shared-context vs clean-context reviewers has been published by any vendor; Cognition's claim is experiential.
- Cursor has not published whether the browser built by hundreds of agents met quality bars.

## What contradicts or extends the orc ticket loop?

### Takeaway
Nothing published contradicts orc's basic shape; the extensions with the strongest evidence are: put the verification standard in the spec before the worker starts, hide acceptance checks from the worker, make the reviewer execute behavior with pre-stated expectations, add in-run stuck/repetition limits, prefer masking over summarizing, keep the rules file short, and route reviewer/tests to a different model.

### Cited Findings
- Scout → spec: Devin confidence-gated questions (asks only when not 🟢) — [Cognition](https://cognition.com/blog/devin-2-1); SWE-grep returns files + line ranges, not prose — [Cognition](https://cognition.com/blog/swe-grep); Factory recommends the plan include "how Droid should verify the work" — [Factory docs](https://docs.factory.com/cli/user-guides/specification-mode)
- Spec content: "Constraints work better than instructions" / "No TODOs, no partial implementations" — [Cursor](https://cursor.com/blog/self-driving-codebases); "DO NOT IMPLEMENT PLACEHOLDER OR SIMPLE IMPLEMENTATIONS" — [ghuntley.com/ralph](https://ghuntley.com/ralph/); standard of completion defined before implementation — [Factory Research](https://factory.com/news/what-it-takes-for-coding-agents-to-complete-large-software-tasks)
- Worker in worktree: Amp sibling-directory worktrees with branch = name and cleanup action — [Amp](https://ampcode.com/news/one-runner-many-worktrees); Augment one worktree per workspace — [Augment](https://augmentcode.com/blog/intent-a-workspace-for-agent-orchestration); Cursor worktrees or remote machines — [Cursor](https://cursor.com/blog/2-0)
- Worker loop limits: Factory stops after three silent turns, nudges at three identical tool calls, stops at six; two attempts per response — [Factory Research](https://factory.com/news/frontier-harness); Ralph `MAX_ITERATIONS` and `WORK_STUCK` signal — [stevekinney.com](https://stevekinney.com/writing/the-ralph-loop)
- Automated checks: linter guardrail worth +3 points (SWE-agent) — [arXiv 2405.15793](https://arxiv.org/html/2405.15793v3); aider auto-lint/auto-test after every edit — [Aider docs](https://aider.chat/docs/usage/lint-test.html); "a type checker is the minimum if there are no tests" — [stevekinney.com](https://stevekinney.com/writing/the-ralph-loop)
- Reviewer passes: clean-context reviewer with no shared context — [Cognition](https://cognition.com/blog/multi-agents-working); expected behavior annotated before each action, assertions passed/failed/untested — [Cognition](https://cognition.com/blog/testing-development); validator instrument hidden from implementer, byte-level comparison — [Factory Research](https://factory.com/news/what-it-takes-for-coding-agents-to-complete-large-software-tasks); different model for review (o3/GPT-5 oracle, Gemini 3 Pro reviewer) — [Amp](https://ampcode.com/news/oracle); [Amp](https://ampcode.com/news/agentic-code-review)
- Fix rounds: coder filters reviewer findings using user context to prevent "looping and out-of-scope work" — [Cognition](https://cognition.com/blog/multi-agents-working); uncapped autofix loop "massively increased" token spend — [Cognition](https://cognition.com/blog/closing-the-agent-loop-devin-autofixes-review-comments); revert and re-plan rather than follow-up fixes — [Cursor docs](https://cursor.com/docs/agent/planning); extra fixer agent introduced bugs — [Augment](https://www.augmentcode.com/blog/1-open-source-agent-on-swe-bench-verified-by-combining-claude-3-7-and-o1)
- Merge: none of the vendors describe fast-forward-only merging; Devin coordinator "resolves any conflicts" — [Cognition](https://cognition.com/blog/devin-can-now-manage-devins); Cursor tolerates turbulence — [Cursor](https://cursor.com/blog/self-driving-codebases)
- Lessons → rules: Playbooks created only when instructions repeat; Session Insights suggests prompt improvements — [Cognition](https://cognition.com/blog/how-cognition-uses-devin-to-build-devin); Telescope clusters failure trajectories — [Replit](https://frontier.replit.com/evaluating-and-improving-agent-at-scale/); compliance drops after 3–4 stacked reminders — [Replit](https://frontier.replit.com/decision-time-guidance/); Ralph signs tuned per observed failure — [ghuntley.com/ralph](https://ghuntley.com/ralph/)
- Context handling: handoff prompt + relevant-files list, editable before sending — [Amp](https://ampcode.com/news/handoff); masking beats summarizing on cost — [arXiv 2508.21433](https://arxiv.org/abs/2508.21433)

### Inferences
- Contradiction candidates: (1) orc's "up to three questions" step is fixed, whereas Devin asks only below green confidence — orc could skip questions on confident tickets; (2) orc's ff-only merge is stricter than any published practice and will require a rebase step the sources do not discuss; (3) Cursor's experiment suggests large tasks need a planner that re-plans continuously rather than a one-shot spec, so orc's spec should be revisable mid-ticket at least by the human.
- Extensions: a completion standard and acceptance checks written before the worker starts and hidden from it (Factory); reviewer "proof" pass executes behavior with pre-stated expectations (Devin); a different model for the reviewer (Amp, Replit, Cognition experiments); an in-run repetition/stuck detector (Factory, Ralph); a short rules file with situational injection (Replit); scout output as file+line ranges (SWE-grep).

### Gaps
- Zed: no harness-design publication was found beyond Agent Panel user docs (tool-call permissions, per-hunk accept/reject, evals required for prompt changes); excluded for lack of mechanism detail — [Zed docs mirror](https://git.secluded.site/zed/blob/nathan/docs/src/ai/agent-panel.md?source=1)
- Warp: Oz docs and press release describe orchestration surface (parent/child harnesses, Docker sandboxes, "hundreds of parallel cloud agents") but no planning, review or context mechanics and no numbers.
- No vendor publishes the effect of a fix-round cap, so orc's "two rounds" is a judgment call unsupported and uncontradicted by published data.
